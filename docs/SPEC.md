# Язык заклинаний Runetime — спецификация v0.1

Единственный источник правды по синтаксису, семантике, опкодам и кодам ошибок.
Реализация обязана соответствовать этому файлу. Расхождение — баг реализации,
а не повод обновить файл по факту.

Язык намеренно похож на книжный псевдокод: явные блоки, `end` вместо отступов,
стрелка присваивания. Ключевые слова и встроенные функции — английские, игрок
пишет код по-английски.

## Пример: рабочее заклинание

```
spell Fireball(target):
    let power <- 12
    let cell <- alloc(power)
    let dmg <- read(cell)
    emit Flame(at: target, power: dmg)
    free(cell)
end
```

## Пример: use-after-free, сценарий B

```
spell Fireball(target):
    let power <- 12
    let cell <- alloc(power)
    free(cell)
    emit Flame(at: target, power: read(cell))
end
```

Компилируется без ошибок. В рантайме `read` по освобождённой ячейке даёт
`R003`: эффект возникает в точке кастующего, а не у цели.

## Грамматика (EBNF)

```ebnf
program     = { spell } ;

spell       = "spell" ident "(" [ params ] ")" ":" block "end" ;
params      = ident { "," ident } ;

block       = { statement } ;
statement   = let_stmt | assign | if_stmt | while_stmt | emit_stmt
            | call_stmt ;

let_stmt    = "let" ident "<-" expr ;
assign      = ident "<-" expr ;
if_stmt     = "if" expr ":" block [ "else" ":" block ] "end" ;
while_stmt  = "while" expr ":" block "end" ;
emit_stmt   = "emit" ident "(" [ args ] ")" ;
call_stmt   = call ;

expr        = or_expr ;
or_expr     = and_expr { "or" and_expr } ;
and_expr    = cmp_expr { "and" cmp_expr } ;
cmp_expr    = add_expr [ ( "<" | ">" | "==" | "!=" ) add_expr ] ;
add_expr    = mul_expr { ( "+" | "-" ) mul_expr } ;
mul_expr    = unary { ( "*" | "/" ) unary } ;
unary       = [ "-" | "not" ] primary ;
primary     = number | "true" | "false" | call | ident
            | "(" expr ")" ;

call        = ident "(" [ args ] ")" ;
args        = arg { "," arg } ;
arg         = [ ident ":" ] expr ;

ident       = letter { letter | digit | "_" } ;
number      = digit { digit } ;
comment     = "#" { any_char_except_newline } ;
letter      = "A" … "Z" | "a" … "z" ;
digit       = "0" … "9" ;
```

Пробелы и переводы строк незначимы, кроме как разделители токенов.
Комментарий от `#` до конца строки.

Зарезервированные слова: `spell` `let` `if` `else` `while` `end` `emit`
`and` `or` `not` `true` `false`. Регистр значим: `Spell` — обычное имя.

### Лексические правила

- `letter` — только ASCII. Любой другой символ вне комментария (кириллица,
  неразрывный пробел, `_` в начале имени, `"`, `.`, `$` и т. п.) — `C001`.
  Внутри комментария допустим любой символ.
- Пробельные символы: пробел, `\t`, `\r`, `\n`. Строку завершает `\n`,
  поэтому `\r\n` работает как один перевод строки.
- Позиция токена — строка и колонка его первого символа, обе с 1. Колонка
  считается в символах Unicode; `\t` занимает одну колонку.
- Токены выбираются жадно, самый длинный вариант: `x<-1` — это `x` `<-` `1`,
  а не `x` `<` `-` `1`. Для сравнения с отрицательным числом нужен пробел:
  `x < -1`.
- Литерал `number` обязан помещаться в `Int` (не больше
  `9223372036854775807`), иначе `C001`. Минус унарный и в литерал не входит,
  поэтому `-9223372036854775808` литералом не записывается.
- Число, за которым вплотную идёт буква или `_` (`12abc`, `12_`), — `C001`.

## Типы

| Тип | Значения | Примечание |
|---|---|---|
| `Int` | знаковое 64-битное целое | единственный числовой тип в v0.1 |
| `Bool` | `true`, `false` | результат сравнений и логики |
| `Cell` | непрозрачный хэндл ячейки | возвращает `alloc`, арифметика запрещена |
| `Entity` | непрозрачная ссылка на сущность | приходит параметром заклинания |

Пользовательских типов в v0.1 нет. Неявных приведений нет: `Int` не является
`Bool`, условие `if 1:` — ошибка `C004`.

## Встроенные функции

| Вызов | Возвращает | Стоимость топлива |
|---|---|---|
| `alloc(value: Int)` | `Cell` | 8 |
| `free(cell: Cell)` | — | 4 |
| `read(cell: Cell)` | `Int` | 2 |
| `write(cell: Cell, value: Int)` | — | 2 |
| `distance(a: Entity, b: Entity)` | `Int` | 2 |

`alloc` выделяет одну ячейку и кладёт в неё `value`. Встроенные функции без
возвращаемого значения (`free`, `write`) нельзя использовать внутри
выражения. Отдельной инструкцией (`call_stmt`) можно вызывать только их.

## Эффекты

`emit` — единственный способ воздействовать на мир. В v0.1 существует один
эффект:

```
emit Flame(at: Entity, power: Int)
```

Именованные аргументы обязательны для `emit`. Стоимость — 16 единиц топлива.

Точка появления эффекта берётся из аргумента `at`. Если `at` получен через
ошибочное обращение к памяти, точкой становится кастующий — см. `R003`.

## Байткод

Стековая машина. Два раздельных стека: стек операндов и стек кадров вызова.
Инструкция — опкод и не более одного операнда.

| Опкод | Операнд | Действие | Топливо |
|---|---|---|---|
| `PUSH_INT` | i64 | положить константу | 1 |
| `PUSH_BOOL` | u8 | положить константу | 1 |
| `LOAD_LOCAL` | u16 | положить значение локальной переменной | 1 |
| `STORE_LOCAL` | u16 | снять верхушку в локальную переменную | 1 |
| `ADD` `SUB` `MUL` `DIV` | — | снять два, положить результат | 1 |
| `NEG` `NOT` | — | снять один, положить результат | 1 |
| `CMP_LT` `CMP_GT` `CMP_EQ` `CMP_NE` | — | снять два, положить `Bool` | 1 |
| `JMP` | u32 | безусловный переход | 1 |
| `JMP_IF_FALSE` | u32 | снять `Bool`, перейти если `false` | 1 |
| `CALL_BUILTIN` | u8 | вызов встроенной функции | по таблице выше |
| `EMIT` | u8 | применить эффект | 16 |
| `RET` | — | выйти из кадра | 1 |
| `HALT` | — | завершить исполнение | 0 |

Других опкодов в v0.1 нет. `and` и `or` компилируются в переходы с коротким
замыканием, отдельных опкодов не получают.

## Топливо

Топливо — игровая мана. Выделяется на один каст, тратится по таблицам выше,
проверяется **перед** исполнением каждой инструкции. При нехватке исполнение
обрывается с `R008`, а уже применённые эффекты остаются в силе.

Это же механизм защиты от бесконечных циклов: `while true:` не вешает игру,
а просто съедает весь запас.

## Ограничения исполнителя

| Предел | Значение v0.1 |
|---|---|
| глубина стека кадров | 64 |
| глубина стека операндов | 256 |
| число локальных переменных на кадр | 64 |
| живых ячеек памяти на каст | 32 |
| размер ячейки | 1 значение `Int` |

Превышение любого — рантайм-ошибка, не паника Rust. VM не должна паниковать
ни на каком входе, включая намеренно испорченный байткод.

## Статические правила

Имена и области видимости:

- Параметры заклинания имеют тип `Entity` и лежат в области тела
  заклинания.
- Каждый блок `if`, `else`, `while` — вложенная область. `let` во вложенной
  области может затенить внешнее имя; после конца блока имя не видно.
- Повторное объявление в той же области — `C006`. Сюда входят `let` с именем
  параметра, повторяющийся параметр и повторяющееся имя заклинания.
- Обращение или присваивание к необъявленному имени — `C002`. Присваивание
  значения другого типа — `C004`.
- Тип переменной — тип выражения в её `let`.

Аргументы:

- Вызов встроенной функции: либо все аргументы позиционные, либо все
  именованные (имена из таблицы выше), именованные — в любом порядке.
- `emit`: только именованные аргументы, в любом порядке.
- Смешивание видов, позиционный аргумент у `emit`, неизвестное или
  повторяющееся имя, неверное число аргументов — `C005`.
- Неизвестная встроенная функция или эффект — `C003`.

Операции:

| Операция | Операнды | Результат |
|---|---|---|
| `+` `-` `*` `/`, унарный `-` | `Int` | `Int` |
| `<` `>` | `Int` | `Bool` |
| `==` `!=` | два `Int` или два `Bool` | `Bool` |
| `and` `or` `not` | `Bool` | `Bool` |

Арифметика (`+` `-` `*` `/`, унарный `-`) над `Cell` или `Entity` — `C007`.
Любое другое несовпадение типов — `C004`.

Компилятор сообщает одну ошибку. Сначала исходник целиком разбирается, и
если в нём есть `C001`, сообщается первая из них. Иначе — первая ошибка
проверки в порядке исходника.

## Ошибки компиляции

Ловятся в гримуаре, до боя. Каждая несёт позицию в исходнике.

| Код | Условие |
|---|---|
| `C001` | неразбираемый токен или синтаксическая ошибка |
| `C002` | обращение к неизвестному имени |
| `C003` | неизвестная встроенная функция или эффект |
| `C004` | несовпадение типов |
| `C005` | неверное число или имена аргументов |
| `C006` | повторное объявление `let` в одной области видимости |
| `C007` | арифметика над `Cell` или `Entity` |

## Ошибки исполнения

Проявляются в бою. Каждая несёт номер инструкции и человекочитаемую причину.

| Код | Условие | Игровое следствие |
|---|---|---|
| `R001` | переполнение стека кадров | кастующий получает тяжёлый урон |
| `R002` | обращение к ячейке, которой не существует | каст уходит в пустоту, топливо потрачено |
| `R003` | чтение или запись освобождённой ячейки | эффект возникает в точке кастующего |
| `R004` | повторное освобождение ячейки | кастующий получает урон |
| `R005` | деление на ноль | урон по площади вокруг кастующего |
| `R006` | переполнение целого | знак эффекта инвертируется |
| `R007` | превышен предел живых ячеек | каст обрывается |
| `R008` | топливо исчерпано | каст обрывается, частичный эффект сохраняется |
| `R009` | переполнение стека операндов | каст обрывается |

## Трассировка

VM ведёт журнал исполнения каста: для каждой инструкции — её номер, опкод,
остаток топлива. Для каждой операции с памятью — номер ячейки и инструкция,
где она была выделена или освобождена. При ошибке журнал обязан дать игроку
ответ на вопрос «почему», без обращения к исходному коду игры.

## Правила изменения этого файла

Любая правка грамматики, таблицы опкодов, стоимости топлива или кодов ошибок
вносится **одним коммитом** вместе с изменением реализации и golden-тестов.
Версия языка хранится в сохранениях рядом с исходником заклинания.
