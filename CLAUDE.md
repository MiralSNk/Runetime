# Runetime

2D-рогалик на Rust, где игрок пишет заклинания кодом. Исполняет их собственная
стековая байткод-VM. Ошибки в коде заклинания — это и есть урон, смерть и порча
инвентаря.

## Текущая задача

**Только v0.1.** Определение готовности и критерии приёмки — `docs/V0_1.md`.
Всё, чего там нет, в работу не берётся, даже если выглядит как очевидный
следующий шаг.

Полная задумка лежит в `docs/DESIGN.md`. Это **справка, а не бэклог**. Не
реализуй оттуда ничего без явной просьбы в сообщении.

## Жёсткие правила

1. **Подложка — `macroquad`.** Свой рендерер, оконный слой, аудио и загрузчик
   ассетов не пишем. Если кажется, что нужен — скажи об этом, не делай.
2. **2D.** Никакой 3D-геометрии, камер, моделей.
3. **Язык кода — английский.** Идентификаторы, комментарии, doc-комментарии,
   имена файлов, сообщения коммитов, тексты тестов.
4. **Язык интерфейса — русский.** Любая строка, которую увидит игрок, живёт
   в `crates/loc` и берётся по ключу. В логике, VM и парсере русских строк быть
   не должно — ни в `println!`, ни в `panic!`, ни в сообщениях об ошибках.
   Диагностика компилятора заклинаний тоже локализуется: код ошибки (`C001`)
   генерируется ядром, текст подставляет `loc`.
5. **Код заклинаний игрок пишет по-английски.** Ключевые слова, встроенные
   функции и имена сущностей в языке заклинаний — только английские.
   См. `docs/SPEC.md`.
6. **VM детерминирована.** Ни одного обращения к генератору случайных чисел
   внутри исполнения заклинания. Рандом живёт только в генерации уровня,
   выпадении награды и поведении врагов — и никогда не влияет на результат
   уже собранного заклинания.
7. **Никакой параллельности в VM.** Ни потоков, ни async, ни разделяемого
   состояния. Гонки данных — тема из `DESIGN.md`, не из v0.1.
8. **Любое изменение языка — сначала в `docs/SPEC.md`, потом в коде.**
   Грамматика, набор опкодов, стоимость топлива и коды ошибок меняются только
   парой «правка спеки + правка реализации + правка golden-тестов» в одном
   коммите.
9. **Каждая семантика VM закрыта golden-тестом.** Файл с исходником
   заклинания → файл с ожидаемым результатом исполнения. Лежат в
   `crates/vm/tests/golden/`. Новый опкод без golden-теста не принимается.

## Структура

```
crates/
  lang/      лексер, парсер, AST, компилятор в байткод, диагностика
  vm/        стековая машина, топливо, память заклинания, трассировка
  game/      арена, сущности, боевой цикл, рендер на macroquad
  loc/       русские строки по ключам
docs/
  SPEC.md    язык заклинаний: грамматика, типы, опкоды, коды ошибок
  V0_1.md    скоуп текущего среза и критерии приёмки
  DESIGN.md  полная задумка (справка, не бэклог)
  GLOSSARY.md соответствие русских терминов и английских идентификаторов
```

`lang` не знает про `vm`. `vm` не знает про `game`. `game` не знает про
внутренности `lang` — только про публичный API компиляции.

## Перед работой прочитай

- правишь язык или компилятор → `docs/SPEC.md`
- добавляешь термин или строку интерфейса → `docs/GLOSSARY.md`
- не уверен, входит ли задача в скоуп → `docs/V0_1.md`

## Гигиена

- `cargo fmt` и `cargo clippy --all-targets -- -D warnings` проходят без
  замечаний до коммита.
- `cargo test` зелёный до коммита.
- Коммиты по Conventional Commits, короткими связными шагами. Не складывай
  парсер, VM и рендер в один коммит.
- Публичные элементы документируются rustdoc, примеры в `# Examples` должны
  быть работающими doc-тестами.

## Чего не делать

- Не вводить зависимости без явного согласования. Если без крейта никак —
  назови его и объясни, зачем, прежде чем добавлять.
- Не «улучшать» грамматику по ходу реализации.
- Не заводить второй редактор заклинаний (граф, дерево). В v0.1 единственный
  источник правды — текст.
- Не писать заглушки, которые молча возвращают успех. Нереализованное должно
  возвращать явную ошибку или `todo!()` с пояснением.
